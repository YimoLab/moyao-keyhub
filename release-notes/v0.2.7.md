## 墨钥 KeyHub 0.2.7

本次更新修正了 Git 托管平台的连接测试判定，并让配置错误更容易被发现。

### Git 托管平台的连接测试

GitHub、GitLab、Gitee、华为云 CodeArts 等服务不提供 shell。此前用 `echo KEYHUB_OK && uname -a` 探测会被平台拒绝，即使密钥配置完全正确也会显示失败。

现在墨钥会自动识别这类平台，改用 `ssh -T` 只做认证探测，并根据服务端欢迎语判定结果。GitHub 返回退出码 1、CodeArts 返回 128 都属正常，不再误报失败；结果卡会标注「认证成功」与「Git 托管（无 shell）」。

### 诊断更贴近真实原因

- Host 的 `User` 被填成仓库路径（例如把 clone 地址里的 `org/repo` 当成用户名）时，直接指出「User 字段填的不是用户名」，并提供「去修改 config」入口。
- Git 托管平台未使用 `git` 用户时，提示正确的用户名约定。
- 别名模式下的公钥拒绝会提醒检查 Host 的 User 与 IdentityFile，而不是只建议改 `authorized_keys`。

### 配置校验

SSH Config 编辑器现在会拦截 `User` 中的 `/`、`\`、`:` 和空格，并说明 Git 托管平台通常固定使用 `git`，仓库路径只属于 clone 地址。
